# [已废止] 交付双模式在内容深度上不同，而非同一份内容换皮

> **Status: deprecated**
>
> HTML 模式已整体移除，本 ADR 不再生效，保留仅供追溯。废止理由见文末。

产出分对话模式与 HTML 模式，由 skill 运行时询问使用者选择。我们决定两者的差异不只是呈现方式，内容深度也不同：对话模式只给骨架、细节全部丢弃、不设附录；HTML 模式给完整展开版，并把压缩掉的细节收进文末附录。

理由是使用者在两种模式之间做的是一个成本权衡——精炼、快、省 token 对上完善、慢、费 token。如果只是换皮，HTML 模式就没有存在理由：没有人愿意多花 token 买回同一份内容。

代价是两种模式无法共用一套写作逻辑，skill 必须分别约束，且附录、悬浮框等机制只存在于 HTML 模式。

## 废止理由

三条，全部指向同一个方向——**砍掉 HTML 模式更能贯彻快原则**：

1. **维护成本**。双模式意味着两套写作约束、两套图表规范、一套额外的排版模板。产出的边际收益撑不起这个成本。
2. **实际效果不达标**。HTML 模板做出来后，视觉呈现未达预期。与其迭代一个次要形态，不如把资源集中在唯一的对话产出上。
3. **少一次交互**。运行时还要问使用者"要对话版还是 HTML 版"，这一轮本身就在消耗快原则。去掉模式之后，开工即写。

**现况**：只有一种交付形态——直接输出在对话里。细节全部丢弃，无附录，术语注释走行内括号，图表用字符图。相关的 `assets/html-template.html` 与"确认交付模式"步骤均已删除。
